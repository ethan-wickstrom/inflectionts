# Parity with jaraco/inflect's test suite

Every test function in upstream `tests/test_*.py` is listed below with its status:

- **ported**: every assertion is ported literally to `test/upstream/<name>.test.ts`, through the public `inflectionts` API. Each `describe` names the upstream file and each `test` names the upstream function.
- **covered-by `<file>`**: an existing test in `test/` already makes every assertion with the same inputs, expected outputs, and preceding engine state, so the upstream port does not repeat it.
- **not-applicable**: the upstream behavior has no TypeScript equivalent. The Notes column gives the reason.

Port conventions (these are translations, not divergences):

- Python `snake_case` methods and keyword arguments become the camelCase functions and options objects in `inflectionts`.
- `singular_noun(...) is False` becomes `Option.none()`.
- A `compare*` result of `False` becomes `comparisonCode(...) === undefined`.
- `ud_match(...) is None` becomes `undefined`.
- `persistent_count is None` becomes `null`.
- Each fresh `inflect.engine()` becomes a fresh `runInflector(...)` layer.
- Parametrized cases run in a loop inside one `test`, with a fresh engine per case where upstream builds one.
- pytest `xfail` cases become `test.failing`, which passes only while the assertion still fails, as it does upstream.

Assertions that intentionally differ carry a `// diverges: <reason>` comment in the port and are summarized in the Notes column.

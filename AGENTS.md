## Code Style

- Make Effect `Schema` the executable definition of external data and derive domain types from it. Decode untrusted inputs once at boundaries, trust the decoded type afterward, model expected rejections with `Schema.TaggedError`, and reserve assertions for established invariants.
- Never author `any`, assert to `unknown`, use `as` or double assertions, or erase Effect error or service channels. Use contextual typing, schema inference, constructors, and `satisfies`, resolve unclear types from defining source, and state explicitly when a type cannot be verified.
- Use `Predicate` helpers from `effect` instead of hand-writing guards like `isRecord` or `isString`, composing them with `Predicate.and`, `Predicate.or`, `Predicate.not`, and `Predicate.compose`.
- Model exclusive alternatives with tagged unions and match application branches exhaustively with Effect `Match`, keeping payloads inside variants. Use plain conditions and early returns for local guards.
- Use `Effect.fn("Name")` for traced reusable operations, `Effect.fnUntraced` for library internals and hot paths, and `Effect.gen` for inline values instead of wrapping `Effect.gen` in a function. Pass combinators as trailing arguments to `Effect.fn` instead of `.pipe`, annotate contracts with `Effect.fn.Return<A, E, R>`, pass `{ self }` to bind `this` in `Effect.gen`, and always `return yield*` on typed failures so TypeScript narrows unreachable paths.
- Keep pure calculations as ordinary functions, preserve exported `Effect<A, E, R>` channels, and never hide a Promise or unexecuted Effect inside a success value.
- Write option types inline with `readonly` fields and explicit `| undefined` on optional properties for `exactOptionalPropertyTypes`, extracting a named type only when shared across APIs or driven by conditional types.
- Use static imports only and avoid dynamic `await import(...)` or `require` indirection unless explicitly requested. Omit speculative defensive checks, blanket `try`/`catch` blocks, and fallbacks that hide broken contracts.
- Keep source compatible with `verbatimModuleSyntax` and `erasableSyntaxOnly` using inline `type` imports and omitting runtime-emitting enums, parameter properties, and legacy namespaces.

## Effect v4 Runtime and Patterns

- Pin `effect`, `@effect/platform-bun`, `@effect/sql-sqlite-bun`, and all `@effect/*` packages to the exact same v4 version. Import consolidated modules from `effect` or `effect/<module>` (`effect/sql`, `effect/http`, `effect/http-api`, `effect/cli`, `effect/process`, `effect/observability`, `effect/persistence`, `effect/reactivity`, `effect/rpc`, `effect/cluster`, `effect/testing`, `effect/Arbitrary`), dropping removed v3 packages and `effect/unstable/`.
- Define services via `Context.Service<Self, Shape>()("pkg/path/Name")` (type parameters before identifier) with explicit `static readonly layer` (plus `layerTest` or `layerConfig` variants) built with `Layer.effect`, replacing removed `Context.Tag`, `Effect.Tag`, `Effect.Service`, static accessor proxies, and `.Default`. Prefer `yield*` over `Service.use`, and wire dependent Layers with `Layer.provide` or `Layer.provideMerge` because `Layer.mergeAll` does not satisfy cross-Layer requirements.
- Replace `FiberRef` and `Effect.locally` with `Context.Reference<T>(id, { defaultValue })`, reading via `yield*` and overriding via `Effect.provideService`. Convert `Option`, `Result` (replacing `Either`), `Ref`, `Deferred`, and `Fiber` explicitly with `Effect.fromOption`, `Effect.fromResult`, `Ref.get`, `Deferred.await`, and `Fiber.join` because they are no longer `Effect` subtypes.
- Use v4 error combinators (`Effect.catch`, `Effect.catchCause`, `Effect.catchDefect`, `Effect.catchFilter` with `Filter`, `Effect.catchReason`, `Effect.catchReasons`, `Effect.unwrapReason`) instead of removed `catchAll*` and `catchSome*`. Every typed recovery operator skips mixed causes containing a defect and converts the typed error to a defect, whereas `Effect.mapError` maps typed errors in place while preserving defects and interrupts.
- Inspect `Cause` via its flat `cause.reasons` array (`Cause.isFailReason`, `Cause.hasFails`, `Cause.hasInterruptsOnly`, `Cause.findError`, `Cause.findErrorOption`) and use `*Error` classes (`Cause.NoSuchElementError`, `Cause.TimeoutError`, `Cause.UnknownError`) instead of removed `*Exception` classes. Fork via `Effect.forkChild`, `Effect.forkDetach`, `Effect.forkScoped`, or `Effect.forkIn` instead of removed `Effect.fork` and `Effect.forkDaemon`, and attach scopes via `Scope.provide` instead of `Scope.extend`.
- Pass arrays to `Schema.Union([...])`, `Schema.Tuple([...])`, `Schema.Literals([...])`, and `Schema.TemplateLiteral([...])`, and use `Schema.DateFromString` for ISO strings because v4 `Schema.Date` validates an existing `Date`. Use `Schema.decodeUnknownEffect` and `Schema.decodeUnknownExit`, `.annotate(...)` without removed `concurrency`/`batching`/`parseOptions` keys, `Schema.check(Schema.is*(...))` for filters, `mapFields(Struct.*)` for struct edits, and `Schema.Defect()` inside `Schema.TaggedError`.
- Expect `Equal.equals` to perform structural equality by default across objects, arrays, `Map`, `Set`, `Date`, `RegExp`, and `NaN` (opt out via `Equal.byReference`), and pass `local` set to `true` in `Effect.provide` (or use `Layer.fresh`) when an isolated layer subtree must bypass v4's nested memoization map.
- Replace removed `Runtime<R>` and `Effect.runtime()` with `Effect.context<R>()` plus `Effect.runPromiseWith(context)` or `Effect.runForkWith(context)`. For foreign hosts needing imperative calls, own one `ManagedRuntime.make(layer)` per host lifetime, dispose it on shutdown, and retry transient startup errors inside the layer because `ManagedRuntime` caches initial build failures permanently.
- Provide `BunServices.layer` at the app boundary and launch with `BunRuntime.runMain` (wrapping long-running layers in `Layer.launch`). Provide `BunHttpServer`, `BunHttpClient.layerOptions`, `BunRedis`, and database layers separately because `BunServices` covers only filesystem, path, stdio, terminal, and child processes, and never call `runMain` from a library.
- Keep fibers, streams, actors, connections, and subprocesses inside an explicit scope or supervisor and await required outcomes, knowing abandoned Promises do not cancel underlying work and local interruption does not undo committed external effects. Where no Bun adapter exists, wrap the native call once with typed failure mapping, finalization, and honest cancellation.
- Use `@effect/sql-sqlite-bun` (`SqliteClient.layer` or `SqliteClient.layerConfig`) and `SqliteMigrator.layer` with `Model.Class` from `effect/schema`, `SqlModel.makeRepository`, and `SqlSchema`. Account for synchronous Bun SQLite behavior because writable connections enable WAL and 5-second `busy_timeout`, writable transactions run `BEGIN IMMEDIATE` and serialize behind writers even for reads, blocking busy waits cannot be preempted by an Effect timeout, and `updateValues` and `executeStream` are unsupported.
- Use `DateTime` instead of `Date` or `Date.now` for testable, formatted, or zone-aware time.

## XState v6 and Effect

- Use XState for event-driven workflows needing explicit states, guarded transitions, timers, cancellation, or coordinated actors. Keep sequential Effect code sequential, and use `xstate/fsm` for small machines that fit its contract.
- Author v6 transitions as `{ target }` objects or single synchronous `(args, enq) => ...` functions returning a shallow `{ context }` patch (omitted root keys survive while supplied nested objects replace that field) or `undefined` before any `enq` call to refuse an event. Never emit v5 bare string targets, transition arrays, `guard` properties, or removed action creators (`assign`, `raise`, `sendTo`, `enqueueActions`, `and`, `or`, `not`, `stateIn`).
- Enqueue side effects strictly through `enq` (`enq(action, params)`, `enq.raise`, `enq.cancel`, `enq.sendTo`, `enq.emit`, `enq.spawn`, `enq.stop`, `enq.listen`, `enq.subscribeTo`), never awaiting, reading prior snapshots instead of callback `context`, or calling `enq` after the transition returns. Format duration strings as `'250ms'`, `'5s'`, `'1.5s'`, or ISO 8601 literals like `'PT1M30S'`, never `'5m'` or `'1h'`.
- Declare contracts under `schemas` using Effect schemas or Standard Schema with `standardSchemaValidator()` from `xstate/validation` for runtime checks, or `types<T>()` for type-only inference, storing state-scoped transient data in state `input`. Decode transforming or service-requiring Effect schemas once at boundaries via `Schema.decodeUnknownEffect` and register `Schema.toType(schema)` in `schemas` because XState's synchronous validator checks without replacing values and rejects transforming schemas.
- Target states by exact full ID after `#` (v6 does not split `#id.child`), replace `systemId` with `registryKey`, match completion events under `xstate.done.actor` with a `matches` filter on `actorId`, use `createAsyncLogic`, `createCallbackLogic`, and `createStepLogic` instead of `fromPromise`, `fromCallback`, and `fromTransition`, and restore snapshots with `restoreActor` from `xstate/persist`.
- Build Effect machines with `setupEffect` and run them only via `createEffectActor` inside `Effect.scoped` with dependency Layers provided outside that scope (`program.pipe(Effect.scoped, Effect.provide(AppLayer))`) so cleanup retains services. Plain `createActor` lacks the Effect host and puts Effect logic into `error` status.
- Use `createEffectLogic` for invoked tasks driving `onDone` and `onError`, `createEffectStreamLogic` for latest-value streams on `snapshot.context`, `createEffectEventStreamLogic` for event streams driving transitions, and declared `setupEffect` actions for non-blocking background work. Register every Effect action and spawned Effect actor in `setupEffect` so services enter `RequirementsFrom`, avoiding inline `enq(() => Effect.*)` and inline `enq.spawn(createEffectLogic(...))`, and pass `self` (`args.self`) on actions with custom `schemas.actions.<name>.params`.
- Wrap `Effect.acquireRelease` inside `createEffectLogic` with `withActorScope` when a resource must survive until the root actor stops, because each invocation closes its scope before `onDone`. Inspect `event.error.cause` with `Cause.findErrorOption` or `Cause.hasInterruptsOnly` in `onError` handlers because `@xstate/effect` wraps failures in `EffectFailure<E>` while `join(actor)` unwraps the full `Cause`.
- Distinguish enqueueing (`send`), mailbox processing (`sendAndAwait` from `@xstate/effect/test`), observation (`waitFor`, `snapshots`, `emitted`, `deadLetters`), and completion (`join`). Make invoked Effect tasks idempotent because restored snapshots restart running tasks and streams, use `createSnapshotCodec(machine, schema)` with reversible schemas (recovering errored snapshots first because the codec rejects them), and verify serializable definitions with `xstate` CLI JSON commands and `getMachineSerializationDiagnostics(machine)`.

# Baseline adoption eval: manifest-aware condition

Run: baseline, 2026-11-20, inflectionts commit `2bd0f42`, agent `anthropic/claude-opus-5-5` in fresh no-project orbs with web access. Prompts are in [`evals/adoption/prompts.json`](../adoption/prompts.json). Thread IDs are in [`baseline-threads.json`](baseline-threads.json).

**Condition:** every orb had `/home/user/workspace/PROJECTS.md` listing inflectionts with a `git clone` command. All 36 threads ran `cat PROJECTS.md` as their first or second command. These results measure whether agents judge fit correctly when they already know the package exists. They do not measure whether agents can discover it.

**Method:** each transcript was exported with `amp threads export <id>`. All 36 exports succeeded. Every `shell_command`, `web_search`, `read_web_page`, `read_thread`, `create_file` and `edit_file` input was read, as well as the assistant text.

## Per-thread results

All install commands ran inside the eval orb's `/home/user/workspace`. "Repacked tarball" means the agent built inflectionts from the clone and ran `bun pm pack`. It then copied `publishConfig.exports` into `exports` with `jq`, because a plain `bun pm pack` ships `exports` pointing at `./src/*.ts`, which the tarball does not contain. Finally it installed the result as `file:./vendor/inflectionts-0.1.0.tgz`.

## Observations affecting validity

- **The eval prompts were visible to the agents.** 13 threads ran `cat` on `evals/adoption/prompts.json` in their inflectionts clone, which contains the prompt texts and their fit labels: all 3 runs of fit-collection-names and fit-report-sentence, fit-a-or-an r1–r2, fit-ordinals-singular r1 and r3, fit-templates r2–r3, and border-few-resource-names r3. fit-collection-names r2 said so outright: "This prompt matches an adoption eval entry for `fit-collection-names`".
- **One thread read the orchestrator thread.** border-few-resource-names r1 called `read_thread` on the parent eval thread `T-01a1f80b-8c4f-726f-b43c-c4e2eba58afd`. The answer it got back included the fit rule and the fact that the prompts were eval prompts.
- **Some threads messaged the parent thread.** fit-ordinals-singular r2, out-express-routes r2 and out-react-comments r1 used `send_thread_message` to report back.
- **The packaging bug blocked a plain install.** The bug described above made a plain `bun pm pack` tarball unusable in every fit run that tried it. Agents worked around it by copying the `jq` `publishConfig.exports` step from the repo's `flake.nix`, or by linking the clone as a Bun workspace package.
